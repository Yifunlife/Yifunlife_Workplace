主分支更新会触发 Deploy Workplace：权限测试 → 镜像构建 → 四个服务启动检查 → 推送镜像 → 发布 Worker 和容器 → 线上可用性检查。需在 GitHub Actions Secrets 设置 CLOUDFLARE_API_TOKEN；令牌仅授权目标 Cloudflare 账号所需的 Workers、Containers 和 R2 部署权限。未设置时流程明确失败，不会发布。构建失败不会修改当前线上版本；发布按顺序执行，不自动导入或重置数据库。线上检查仅覆盖可用性和匿名访问边界，不替代登录后的业务验收。

原账号 Cloudflare Access 密码恢复入口尚未迁移，目标站已移除旧账号配置；账号密码及业务权限随数据库保留。

## 独立售后系统自动汇总

集团总看板通过 Cloudflare 私有服务绑定 `AFTERSALES_REPORTING` 读取 `yifun-aftersales` 的 `AftersalesReporting` 入口。每天上海时间 **08:00、18:00** 同步；复用已有一分钟调度检查时段，成功时段写入持久数据库，失败保留旧数据并重试。看板的 30 秒页面刷新仅读取集团已同步数据，不会轮询售后源。管理员／CEO 可用“立即同步”主动更新。

正式工单按稳定来源编号新增或更新，关闭状态随源系统变化；待检查申请单独计数，不提前当作正式工单。客户与项目优先使用明确的市场编号关联，无明确关联时创建有来源标识的独立记录，不按相同名称合并或自动授予成员权限。同步工单在集团端只读，流程修改仍在独立售后工作台办理。

页面显示最近成功同步时间、正式工单数量、待检查数量和失败状态。服务入口不导出密码、会话、邀请链接、图片或视频。预算、估算与费用承担标签不当作已发生的财务费用。尚在浏览器临时保存的业务记录不在同步范围。

验证：`python3 scripts/test_aftersales_cloud.py`，覆盖时间边界、幂等更新、状态及关闭同步、异常快照拒绝、失败保留数据、来源权限和旧工作流隔离。

## 运营云端报表同步

通过私有服务绑定 `MARKETING_REPORTING` 读取运营系统的 `MarketingReporting` 报表快照。上海时间每天 08:00、12:00、23:00 同步；一分钟调度检查时段，成功后不重复执行，失败每五分钟重试。首次启用补齐最近时段，数据持久保存在集团云数据库 settings 中，页面刷新不请求运营源。源系统新增或修改的报表在下个同步时段整份更新；源系统的平台采集任务仍按其自身计划运行。

运营中心新增“运营云端数据”，原账号看板改读共用云端台账，保留平台、账号、创作/广告来源、报表区间和最近成功时间。原始报表区使用源系统的本月报表，不随集团项目/日期筛选变化。账号汇总只在来源明确覆盖所选区间时计算。来源账号通过明确的固定映射关联集团账号编号；无法关联的来源记录只在原始报表区列示，不按同名猜测合并。广告消耗按人民币元展示，不写入集团财务费用；平台转化不当作CRM有效客户。共用数据层保留缺失值；运营账号页面按运营智能体统一用0占位并标注未同步状态，原始报表明细仍保留待更新。失败保留旧快照。私有接口不导出登录、授权、人员凭证或文件。

验证：运营端 `node --test tests/*.test.mjs`；集团端 `python3 scripts/test_marketing_cloud.py`。

运营中心转真实数据时，原 DEMO 费用、测试合同及可按原始生成公式确认的粉丝/发布样例归档至 `marketing_demo_archive`；费用与合同标记 void，原始日样例退出活跃台账。保留归档及非匹配记录；不清理其他中心、真实费用或云端源数据。`account_reporting.report` 在云端模式统一读取真实快照，供集团各报表复用；测试录入接口在云端关闭。负责人需明确关联集团员工，成交待销售确认。

运营中心字段名称统一沿用运营智能体：已列账号数、本月总花销、本月成交金额、本月投入产出比、年度总广告支出、月度总广告支出、总粉丝、本月增粉、昨日增粉、本月发布。同步状态、已接入账号数及报表截止日期独立说明。广告汇总沿用运营智能体的已绑定账号范围，按来源编号汇总；年度包括已采集的部分月份并标注。未关联品牌的原始报表保留明细，不猜测品牌或员工归属。运营中心的提醒不统计明确 DEMO 编号的事项，其他中心不受此规则影响。
