# 集团售后工作台接入（2026-10-19）

来源：用户提供的售后中心 V10 源码包。集团导航内的“售后工作台”挂载同源页面，沿用现有集团账号、项目权限、CSRF、云端数据库和 R2 文件存储，不导入原员工密码或会话表。

- `/aftercare/workspace`：内部售后工作台；`/aftercare/customers`：客户档案与工单收件箱。
- `/aftercare/request?token=...`：邀请限定的中文、英文、阿拉伯语客户报修与进度页面。
- `/api/aftercare/*`：集团服务端授权后处理。仅 portal、submit 和携带有效邀请 token 的 file 可以匿名访问。
- `af2_*` 表由新增迁移 040 建立，旧员工、库存、付款和售后表不被覆盖。
- 内部手工/Excel 登记按显式选择的集团项目关联；每条工单采用 UUID，草稿与已提交分别保存；附件落集团 R2。
- 已提交问题同步同 ID 的 service_tickets，保留旧的库存领用等原字段，供现有驾驶舱、问题分析与待办使用。原售后记录首次读取时适配到新工作台。
- 内部岗位随集团身份映射；工程账号分配售后职责后映射审核员，分配生产职责后映射生产人员。CEO 和共享查看账号只读。所有业务继续受原项目成员权限约束。
- 不挂载原源码的会话内独立仓库、安装、财务演示面板；仓库/安装沿用主售后流程的云端任务，集团原仓库/财务台账继续是库存和实际费用的权威来源。售后处理界面里的拟报费用不直接视为付款凭证。
- 故障与根因追踪单独补充设备序列号、款式、区域、故障日期、启用日期、上次维修日期、根因证据和改善验证，进入现有问题统计。没有证据不能标记根因已验证，没有设备编号不推断同台复发。
- 月/季/年报告仍保留底部预览；本次未提供 PPTX 下载。

`public` 为已构建、可直接随集团容器发布的静态资源。React 客户页面的作者源码在 ui-src；依赖锁定后执行 node build.mjs 可重新构建。workflow-*.js 从来源 HTML 分离并适配为同源受保护脚本。原 intake-schema.json 与 XLSX 模板字段未变，额外项目选择属于集团关联上下文。

验证入口：scripts/test_aftercare_integration.py；原云端账号检查也会调用该测试。检查包括草稿/提交持久化、版本冲突、项目隔离、客户多问题与附件、专员交审核、验收关闭及客户可见状态。

源码包不含原售后站点的 D1/R2 数据，故本次并入的是功能与集团已有记录；原站历史客户链接、业务数据和附件未迁移，不会因复制源码自动同步。
